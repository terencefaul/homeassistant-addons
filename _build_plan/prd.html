Gate PIN

A Home Assistant add-on that gives a visitor a short-lived credential — a 6-digit PIN you can read over the phone, or a tokenised link you send them — which operates only the entities you chose, only for as long as you allow. You mint and revoke credentials from a Telegram bot or an admin panel inside Home Assistant; the visitor gets a mobile page at gate.terica.co.za and access to nothing else.

Home Assistant add-on Python 3.12 FastAPI Pydantic SQLite nginx React 19 Vite Tailwind 4 Cloudflare Tunnel

What the app does

  • Mint a guest credential

    Pick entities, set a window, choose a PIN, a link, or both. Get back the code, the link and a QR — once.

  • Guest access page

    A mobile page that takes a PIN or a link, then shows only the allowed entities with live state and one tap each.

  • Telegram control

    Mint, list, extend and revoke from your phone. Saved presets mean /new plumber is the whole command.

  • Live grant management

    See what's active and when it dies. Extend a live grant, or revoke it instantly — killing any session already open.

  • Audit log

    Every redemption, action, refusal and wrong code — with time, entity and visitor IP.

  • Abuse protection

    Rate limiting, a cap on live PINs, and a lockout with an alert when someone starts guessing.

  • Admin panel inside Home Assistant

    A sidebar panel behind your existing HA login. No second account. Installable as an app on your phone.

  • Camera streams (admin only)

    A stream button under each camera in the admin panel, so you can see who is actually at the gate.

Already provided by the Home Assistant add-on platform

The add-on platform is the starter template here. None of this gets re-specced or re-built.

  • Admin authentication via ingress
  • Sidebar panel
  • Install and update flow
  • Options UI with schema validation
  • /data persistence, inside HA backups
  • SUPERVISOR_TOKEN for HA API access
  • Multi-arch base images and build pipeline
  • Log viewer

Out of scope (v1)

  • Visitor identity or accounts — a credential is a bearer token. No login, no profile, no history tied to a person.
  • Use counting and one-time codes — deliberately dropped. The time window is the only control.
  • Self-service credential requests — the bot is admin-only. A visitor cannot ask it for a code.
  • Approve / deny request flow — no pending-request state to build, expire or explain.
  • Recurring or scheduled-repeating grants — a grant can start later, but there is no "every Tuesday at 08:00".
  • Camera streams on the guest page — a public endpoint is the wrong place for video. Admin panel only.
  • Companion Home Assistant integration — exposing grants as HA entities to automate on comes after the add-on is stable.
  • Service worker on the guest page — offline is meaningless for a gate, and a service worker persists on a visitor's phone after the credential dies. One of the few choices that cannot be fixed forward.
  • PostgreSQL, and TLS without Cloudflare — SQLite and tunnel-only. Revisit if this is published to installers without a tunnel.
  • Multi-admin roles and permissions — anyone with Home Assistant access can mint.
  • Arbitrary JS or HTML injection into the guest page — the base add-on allowed this. It is how a third-party asset gets added back in and leaks the token via the referrer header.

External integrations

Telegram Bot API

Minting

How you mint, list, extend and revoke credentials from your phone without opening Home Assistant. Telegram is used rather than HA notifications because you can forward the message carrying the link straight to the visitor.

Credentials needed

  • Bot token from @BotFather
  • Your numeric chat ID from @userinfobot

Cloudflare Tunnel

Public access

Makes gate.terica.co.za reachable from the internet with no inbound port open on your connection, and terminates HTTPS at the edge. It also supplies the visitor's real IP, which the rate limiting depends on.

Credentials needed

  • Tunnel token from Cloudflare Zero Trust

Home Assistant API

Entities

How the add-on reads entity state, calls services, proxies camera feeds, and sends alert notifications to your phone. Not really external — Supervisor injects the token automatically.

Credentials needed

  • None — nothing to sign up for or rotate
  • The name of your notify.* service, for alerts

Milestones

1

Live gate access

Everything needed to let a real visitor in: the add-on itself, minting from the admin panel, the guest page, and the public route — hardened before it goes live.

What gets built

  • An installable add-on that appears in your add-on store, starts, and shows a panel in the Home Assistant sidebar
  • A mint form: label, searchable entity picker, duration presets or custom, a start-later option, theme, and PIN / link / both
  • A result screen showing the PIN large, the link with copy, and a QR code — with a clear warning it will not be shown again
  • The guest page: PIN entry, link auto-submit with the code stripped from the address bar, allowed entities with live state, one tap each
  • Distinct, honest messages for wrong code, not active yet, expired, revoked, and the gate not answering
  • Rate limiting, the live-PIN cap, and the lockout that fires an alert
  • The public route through Cloudflare Tunnel, with the visitor's real IP reaching the rate limiter
  • A basic revoke, so a credential minted in error can be killed

Not in this milestone

  • The Telegram bot — minting is admin-panel only for now
  • Saved presets
  • Extending a live grant
  • The audit log view — activity is recorded, but there is no screen for it yet
  • Camera streams
  • Logo and accent-colour branding — themes only
  • Making the admin panel installable as an app

Done when: from a phone on mobile data — not on your home wi-fi — you open gate.terica.co.za, type a PIN you just minted, and the gate opens. A wrong code is refused and slows you down on repeat attempts. A code you revoked stops working immediately, even in a tab that was already open.

2

Admin panel and Telegram control

Turns a working system into one you'd actually use daily — the full admin experience, and control from your phone without opening Home Assistant.

What gets built

  • Saved presets — name a set of entities, duration, theme and credential kinds, then mint from it in one tap
  • Grant management: what's active, what it allows, a countdown to expiry, extend a live grant, revoke instantly
  • The live-PIN count against its cap, always visible
  • Audit log screen: chronological, filterable by grant and by what happened, including wrong codes belonging to no grant
  • A stream button under each camera entity, showing a live view inside the admin panel
  • Branding: upload a logo, pick an accent colour, set the default theme — applied to guest pages
  • The admin panel becomes installable on your phone, with an offline shell
  • The Telegram bot: mint, mint-from-preset, list, extend, revoke — PIN and link sent as separate messages
  • Alerts to your Home Assistant app when someone starts guessing codes, or the bot stops responding
  • A health view showing whether the bot is alive

Not in this milestone

  • Visitors talking to the bot, or any approve/deny flow
  • Editing a grant's entities or theme after minting
  • Reviving an expired grant
  • Charts, CSV export, or user-defined alert rules
  • Camera streams on the guest page
  • Tuning rate limits from the interface
  • The companion Home Assistant integration

Done when: you send /new plumber to the bot, get a PIN and a link in two separate messages, forward the link, watch the redemption appear in the audit log, check the driveway camera from the admin panel on your phone, and revoke the grant from Telegram — all without opening Home Assistant on a computer.
